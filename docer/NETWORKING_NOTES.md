# Особенности сетевого взаимодействия в Docker

### 1. Локальный запуск с 127.0.0.1
При запуске сервисов напрямую на хост-машине (без Docker), все процессы делят общую сетевую карту хоста. `127.0.0.1` (localhost) указывает на саму хост-машину. Поэтому сервисы легко видят друг друга через порты (например, `http://127.0.0.1:8001`).

### 2. Неудачный запуск контейнера с 127.0.0.1
Если внутри контейнера `order-service` вызвать `http://127.0.0.1:8001`, произойдет ошибка. Внутри контейнера `127.0.0.1` изолирован и указывает **на сам этот контейнер**, а не на хост или соседний сервис. Так как внутри `order-service` на порту 8001 никто не слушает, запрос упадет.

### 3. Успешное взаимодействие через имена сервисов
В Docker Compose (или общей Docker-сети) встроен DNS-сервер. Когда контейнеры находятся в одной сети, они могут обращаться друг к другу по именам сервисов (или `container_name`). Запрос `http://product-service:8000` успешно дойдет, так как Docker сам преобразует имя `product-service` во внутренний IP-адрес нужного контейнера.

### 4. Взаимодействие через хост (host.docker.internal)
Если контейнеру необходимо достучаться до сервиса, который работает *вне контейнера* (на хостовой машине), адрес `127.0.0.1` не сработает по причинам из п.2. Для этого в Docker предусмотрен специальный DNS-запись `http://host.docker.internal`, который перенаправляет трафик из контейнера обратно на хост-машину.
